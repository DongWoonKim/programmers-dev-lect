# 코루틴

> 파일 하나에 연습 함수를 하나씩 늘려 가면서, **"기다리는 일을 어떻게 겹치는가"** 확인합니다.

---

## 1. 무엇을 하나요?

상품 정보를 서버에서 가져오는 상황을 흉내 냅니다. 서버 응답은 `delay` 로 대신합니다.

```
[문제 3] 순차 조회
상품1 / 상품2 / 상품3
걸린 시간: 1521ms

[문제 4] 동시 조회
상품1 / 상품2 / 상품3
걸린 시간: 512ms      <- 같은 일을 했는데 3분의 1
```

**출력 내용은 똑같고 시간만 다릅니다.** 이 차이를 만드는 것이 이번 복습의 전부입니다.

---

## 2. 학습 목표

|개념|어디서 쓰나|
|---|---|
|`suspend`|기다릴 수 있는 함수 만들기 (문제 1)|
|`delay`|`Thread.sleep` 과 무엇이 다른가 (문제 1, 8)|
|`runBlocking`|보통 함수에서 코루틴으로 들어가기 (문제 2)|
|`launch`|결과가 필요 없는 일 띄우기 (문제 2)|
|`async` / `await`|결과가 필요한 일 띄우기 ⭐ (문제 4)|
|`awaitAll`|여러 개를 한꺼번에 기다리기 (문제 5)|
|`coroutineScope`|함수 안에서 여러 개를 동시에 처리하기 ⭐ (문제 6)|
|`cancelAndJoin`|도중에 멈추기 (문제 7)|
|`withTimeoutOrNull`|시간 제한 두기 (문제 7)|
|구조화된 동시성|자식이 죽으면 형제도 취소된다 (문제 9)|


### (2) 파일 만들기

`src/main/kotlin/CoroutinePractice.kt` 를 만들고 아래를 먼저 써 둡니다.

```kotlin
import kotlinx.coroutines.*
import kotlin.system.measureTimeMillis

// 서버에서 상품 이름을 가져오는 셈 친다. 0.5초가 걸린다.
suspend fun fetchName(id: Int): String {
    delay(500)
    return "상품$id"
}

// 서버에서 가격을 가져오는 셈 친다.
suspend fun fetchPrice(id: Int): Int {
    delay(500)
    return id * 1000
}

fun main() {
    // 문제를 풀 때마다 여기에 한 줄씩 추가한다
}
```

> 💡 **`measureTimeMillis { }`** 는 블록을 실행하는 데 걸린 시간(ms)을 돌려줍니다. 이번 복습에서 계속 씁니다.
> ```kotlin
> val time = measureTimeMillis { /* 잰다 */ }
> println("걸린 시간: ${time}ms")
> ```

### 문제 1. suspend 는 왜 필요한가

**목표**: `suspend` 를 빼면 어떤 에러가 나는지 **눈으로 확인**한다.

**할 일**

1. 준비 단계에서 쓴 `fetchName` 에서 `suspend` 를 지워 본다.
2. 어떤 에러가 나는지 읽어 본다.
3. 다시 `suspend` 를 붙인다.
4. 이번엔 `suspend` 를 지운 채로 `delay(500)` 을 `Thread.sleep(500)` 으로 바꿔 본다. 컴파일이 되는가?

**확인**: 3번에서 나온 에러 메시지를 그대로 적어 보세요.

> ⭐ **에러가 말하는 것**: `delay` 가 suspend 함수이기 때문에, 이것을 부르는 함수도 suspend 여야 합니다. `suspend` 는 붙여도 되고 말아도 되는 장식이 아니라 **`delay` 같은 함수를 쓰기 위한 입장권**입니다.
> 4번이 컴파일되는 이유는 `Thread.sleep` 이 자바 함수라 코루틴과 무관하기 때문입니다. **대신 그동안 스레드를 통째로 붙잡습니다.** 되는 것과 좋은 것은 다릅니다.

### 문제 2. runBlocking 과 launch — 출력 순서 맞히기

**목표**: `launch` 가 "띄우고 바로 넘어간다"는 것을 순서로 확인한다.

**할 일**: 아래 코드를 실행하기 **전에** 출력 순서를 예상해서 적어 보세요. 그다음 실행해서 맞는지 봅니다.

```kotlin
fun ex2() = runBlocking {
    println("A")

    launch {
        delay(1000)
        println("B")
    }

    println("C")
}
```

**예상**: ( ) → ( ) → ( )

**확인**: `A → C → B` 가 나오면 성공. 세 가지를 설명할 수 있어야 합니다.

1. `C` 가 `B` 보다 먼저 나오는 이유는?
2. 그런데도 `B` 가 **반드시** 출력되는 이유는? (`runBlocking` 이 무엇을 해 주나요)
3. `runBlocking` 을 지우면 왜 컴파일이 안 되나요?

> 💡 **한 걸음 더**: `launch { }` 를 하나 더 추가하고 안쪽 `delay` 를 `500` 으로 줘 보세요. 출력 순서가 어떻게 되나요?

### 문제 3. ⭐ 순차 실행의 벽

**목표**: suspend 함수를 **그냥 부르면** 동시에 실행되지 않는다는 것을 시간으로 확인한다.

**할 일**: 상품 3개의 이름을 가져와 출력하고, 걸린 시간을 잰다.

**힌트**

```kotlin
fun ex3() = runBlocking {
    val time = measureTimeMillis {
        val a = fetchName(1)
        val b = fetchName(2)
        val c = fetchName(3)
        println("$a / $b / $c")
    }
    println("걸린 시간: ${time}ms")
}
```

**확인**: 약 **1500ms** 가 나오면 성공(0.5초 × 3).

> ⭐ **여기가 출발점입니다.** `fetchName` 은 suspend 함수인데도 세 번이 순서대로 실행됐습니다.
> **`suspend` 는 "멈췄다 갈 수 있다"는 표시일 뿐, 그 자체로 동시에 실행되게 만들지 않습니다.**
> 두 번째 줄은 첫 번째 줄이 끝나야 시작합니다. 서버 3곳에 요청할 때 이러면 응답 시간이 그대로 더해집니다.

### 문제 4. ⭐ async / await — 1500ms 를 500ms 로

**목표**: 문제 3의 코드를 고쳐서 셋이 **동시에** 진행되게 만든다.

**할 일**

1. 세 번의 호출을 `async { }` 로 감싼다.
2. 세 개를 **다 띄운 다음에** `await()` 로 결과를 받는다.

**힌트**

```kotlin
fun ex4() = runBlocking {
    val time = measureTimeMillis {
        val a = async { fetchName(1) }      // 시작만 시킨다. 즉시 다음 줄로 간다
        val b = async { fetchName(2) }
        val c = async { fetchName(3) }
        println("${a.await()} / ${b.await()} / ${c.await()}")   // 이제 결과를 받는다
    }
    println("걸린 시간: ${time}ms")
}
```

**확인**: 약 **500ms**. 출력 내용은 문제 3과 **똑같아야** 합니다.

> ⭐ **`async` 는 결과 대신 `Deferred` 라는 "상자"를 즉시 돌려줍니다.** 값은 아직 없고, 0.5초 뒤에 채워질 자리입니다.
> 상자 3개를 **먼저 받아 두고 나중에 여는 것**이 핵심입니다.

**⚠️ 흔한 실수 — 직접 해 보세요**

```kotlin
val a = async { fetchName(1) }.await()      // 만들자마자 열어 버린다
val b = async { fetchName(2) }.await()
val c = async { fetchName(3) }.await()
```

이렇게 바꾸면 몇 ms가 나오나요? 왜 그럴까요?

### 문제 5. awaitAll — 개수가 늘어나도 똑같이

**목표**: 상품 **10개**를 동시에 조회한다. 컬렉션 함수와 이어 붙인다.

**할 일**

1. `(1..10).map { }` 으로 `async` 10개를 만든다.
2. `awaitAll()` 로 한꺼번에 기다린다.

**힌트**

```kotlin
fun ex5() = runBlocking {
    val time = measureTimeMillis {
        val names = (1..10).map { id -> async { fetchName(id) } }   // 10개를 전부 띄우고
            .awaitAll()                                             // 한꺼번에 기다린다
        println(names)
    }
    println("걸린 시간: ${time}ms")
}
```

**확인**: 5000ms 가 아니라 약 **500ms**. `names` 는 `List<String>` 입니다.

> ⭐ **10개든 100개든 시간이 같습니다.** `(1..100)` 으로 바꿔서 직접 확인해 보세요. 순차로 하면 50초 걸릴 일이 0.5초에 끝납니다.
> `map` 은 이미 배운 컬렉션 함수 그대로입니다. **새로 배운 것은 `async` 하나뿐인데 할 수 있는 일이 완전히 달라집니다.**

### 문제 6. ⭐ coroutineScope — 함수로 묶기

**목표**: 동시 조회를 **함수 하나로** 만든다. 그 과정에서 `async` 가 아무 데서나 쓰이지 않는다는 것을 확인한다.

**할 일**

1. 상품 하나의 이름과 가격을 **동시에** 가져와 `"상품1 (1000원)"` 형태로 돌려주는 함수를 만든다.
2. 먼저 `suspend fun` 으로만 써 보고 **컴파일 에러를 확인**한다.
3. `coroutineScope { }` 로 감싸서 해결한다.

**먼저 이렇게 써 보세요 (에러가 납니다)**

```kotlin
suspend fun fetchProduct(id: Int): String {
    val name = async { fetchName(id) }      // ✗ 에러
    val price = async { fetchPrice(id) }
    return "${name.await()} (${price.await()}원)"
}
```

**힌트**

```kotlin
suspend fun fetchProduct(id: Int): String = coroutineScope {
    val name = async { fetchName(id) }
    val price = async { fetchPrice(id) }
    "${name.await()} (${price.await()}원)"      // 마지막 식이 반환값
}

fun ex6() = runBlocking {
    val time = measureTimeMillis { println(fetchProduct(1)) }
    println("걸린 시간: ${time}ms")             // 약 500ms
}
```

**확인**: `상품1 (1000원)` 이 약 500ms 에 나오면 성공.

> ⭐ **왜 `suspend` 만으로는 안 되나요?** `async` 는 `CoroutineScope` 의 확장 함수입니다. 즉 부르려면 `this` 가 `CoroutineScope` 여야 합니다.
> `runBlocking { }` 중괄호 안에서는 `this` 가 CoroutineScope 라서 그냥 쓸 수 있었지만(문제 4·5), **보통의 suspend 함수 안에는 그것이 없습니다.** `coroutineScope { }` 가 그 자리를 만들어 줍니다.

> ⚠️ **여기서 `runBlocking` 을 쓰면 안 됩니다.** 문법적으로는 되지만, `runBlocking` 은 기다리는 동안 **스레드를 붙잡습니다.** 이미 코루틴 안인데 다시 스레드를 막으면 코루틴을 쓰는 의미가 사라집니다.
> **기준은 "main 이냐"가 아니라 "이미 코루틴 안이냐"** 입니다. 코루틴 밖에서 들어갈 때만 `runBlocking`, 이미 안이면 `coroutineScope` 입니다.

> 💡 `= coroutineScope { }` 는 식 본문이라 **블록의 마지막 식이 반환값**입니다. 마지막 줄을 지우면 `Unit` 이 되어 타입 에러가 납니다. 직접 지워 보세요.

### 문제 7. 취소와 타임아웃

**목표**: 도중에 멈추기와 시간 제한을 각각 확인한다.

**할 일 (7-1) 취소**

1. `launch` 로 1부터 10까지 세는 코루틴을 띄운다. 한 번 셀 때마다 `delay(200)`.
2. 0.5초 뒤에 취소한다.

**힌트**

```kotlin
fun ex7() = runBlocking {
    val job = launch {
        repeat(10) { i ->
            println("  작업 중 $i")
            delay(200)
        }
        println("  이 줄은 실행되지 않는다")
    }

    delay(500)
    job.cancelAndJoin()          // 취소하고, 정리될 때까지 기다린다
    println("취소 완료")
}
```

**할 일 (7-2) 타임아웃**

3초가 걸리는 함수를 만들고, 1초 제한을 걸어 본다.

```kotlin
suspend fun fetchSlow(): String {
    delay(3000)
    return "느린 응답"
}

// ex7 에 이어서
val result = withTimeoutOrNull(1000) { fetchSlow() }
println("결과: $result")                                  // null

val ok = withTimeoutOrNull(1000) { fetchName(1) }
println("여유 있을 때: $ok")                               // 상품1
```

**확인**: `작업 중 0, 1, 2` 까지만 나오고 "이 줄은 실행되지 않는다" 가 안 나오면 성공. 타임아웃은 `null` 이 나와야 합니다.

> ⭐ **타임아웃은 그냥 포기하는 것이 아닙니다.** 시간이 지나면 안에서 돌던 코루틴을 **실제로 취소**합니다. 응답을 버리고 넘어가는 게 아니라 일 자체를 멈추기 때문에 자원이 새지 않습니다.

> 💡 **`withTimeout`** 은 `null` 대신 예외를 던집니다. 늦은 것을 **실패로 다뤄야 하면** `withTimeout`, **대체값으로 넘어가면 되면** `withTimeoutOrNull` 입니다.
> ```kotlin
> val name = withTimeoutOrNull(1000) { fetchName(1) } ?: "이름 없음"
> ```

### 문제 8. ⭐ Thread.sleep 을 섞으면

**목표**: 코루틴 안에서 스레드를 막는 코드를 부르면 어떻게 되는지 **직접 겪어 본다.**

**할 일**

1. 문제 5의 코드에서 `fetchName` 의 `delay(500)` 을 `Thread.sleep(500)` 으로 바꾼다.
   (`suspend` 는 그대로 두면 컴파일은 됩니다)
2. 시간이 어떻게 달라지는지 잰다.
3. 다시 `delay` 로 되돌린다.

**확인**: 500ms 였던 것이 몇 ms가 되나요?

> ⭐ **`delay` 는 "여기까지 했다"를 적어 두고 스레드에서 내려옵니다.** 그동안 그 스레드는 다른 코루틴을 실행하러 갑니다.
> **`Thread.sleep` 은 스레드를 그대로 붙잡습니다.** 자리를 맡아 둔 채 기다리는 것이라, 아무리 코루틴을 많이 띄워도 동시에 진행되지 않습니다.
> 실무에서 옛날 방식의 DB·HTTP 호출을 코루틴 안에서 그냥 부르면 이 일이 그대로 벌어집니다. **코루틴을 썼다고 저절로 빨라지지 않습니다.**

**추가로 해 볼 것**: 문제 7의 취소 코드에서 `delay(200)` 을 `Thread.sleep(200)` 으로 바꾸면 취소가 될까요? 직접 확인해 보세요.

> 💡 취소는 **협조적**입니다. `delay` 같은 suspend 함수가 "취소됐나?"를 확인해 주기 때문에 멈추는 것입니다. 확인해 주는 코드가 없으면 취소 신호를 보내도 계속 돕니다.

### 문제 9. 구조화된 동시성 — 하나가 죽으면

**목표**: 자식 코루틴 하나가 실패하면 형제도 취소된다는 것을 확인한다.

**할 일**: 아래 코드를 실행하기 전에 무엇이 출력될지 예상해 보세요.

```kotlin
fun ex9() = runBlocking {
    try {
        coroutineScope {
            launch {
                delay(1000)
                println("  느린 작업 완료")
            }
            launch {
                delay(100)
                throw RuntimeException("일부러 낸 오류")
            }
        }
    } catch (e: Exception) {
        println("예외를 받았다: ${e.message}")
    }
}
```

> ⭐ **스레드였다면** 죽은 스레드 하나만 조용히 사라지고 나머지는 계속 돌았을 것입니다. 그리고 그 예외를 **밖에서 잡을 방법도 없습니다.**
> 코루틴은 부모-자식 관계가 있어서 실패가 위로 전파되고, 형제도 함께 정리됩니다. **반쪽만 성공한 애매한 상태가 남지 않습니다.**

> 💡 자식 하나가 죽어도 형제를 살려 두고 싶다면 `supervisorScope { }` 를 씁니다.
