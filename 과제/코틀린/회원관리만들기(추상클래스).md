# 회원 관리 프로그램 만들기 (추상 클래스 · 다형성)

> 배열 버전으로 만든 회원 관리 프로그램을 **객체지향으로 다시 만듭니다.** 회원에 **등급(일반/VIP)** 이 생기고, 등급마다 월회비가 다릅니다. `abstract class` 로 공통을 묶고 달라지는 부분만 자식이 채우게 만듭니다. **아래 Step을 순서대로 따라가면, 마지막 Step에서 프로그램이 완성됩니다.**
>
> **선행 과제**: `회원관리만들기(배열)` — 같은 프로그램을 배열과 최상위 함수로 만들어 본 상태를 전제로 합니다.

---

## 1. 무엇을 만드나요?

기능은 배열 버전과 같습니다. 대신 회원을 추가할 때 **등급을 고르고**, 전체 조회에 **월 예상 매출**이 붙습니다.

```
[요금제를 선택하세요]
[1]Lite : 10명 [2]Basic : 20명 [3]Premium : 30명
> 1

[수행할 업무를 선택하세요 - 현재 회원수 : 0/10]
[1]회원추가 [2]회원조회(메일) [3]회원조회(이름)
[4]회원전체조회 [5]회원정보 수정 [6]회원삭제
[7]프로그램 종료
> 1

이름을 입력하세요.
> 홍길동
이메일을 입력하세요.
> hong@a.com
연락처를 입력하세요.
> 010-1111-1111
등급을 선택하세요. [1]일반(10000원) [2]VIP(8000원)
> 2
VIP 회원이 등록되었습니다.
```

전체 조회를 하면 이렇게 나옵니다.

```
> 4
1. [일반] [이름] 홍길동, [이메일] hong@a.com, [연락처] 010-1, [월회비] 10000원
2. [VIP] [이름] 김VIP, [이메일] vip@a.com, [연락처] 010-2, [월회비] 8000원
월 예상 매출 : 18000원
```

VIP 회원을 이메일로 조회하면 **VIP에게만** 사은품 안내가 따라옵니다.

```
> 2
이메일을 입력하세요.
> vip@a.com
[VIP] [이름] 김VIP, [이메일] vip@a.com, [연락처] 010-2, [월회비] 8000원
  → 김VIP 님께 VIP 사은품을 보냈습니다.
```

|번호|기능|설명|

## 3. 학습 목표

|개념|어디서 쓰나|
|---|---|
|`abstract class`|`Member` — 실체 없는 개념이라 객체를 만들 수 없게 막는다|
|추상 프로퍼티|`abstract val grade: String` — 값 없이 선언만, 자식이 채운다|
|추상 메서드|`abstract fun monthlyFee(): Int` — 등급마다 계산이 다르다|
|상속과 `override`|`class VipMember(...) : Member(...)`|
|`toString()` 재정의|`println(회원객체)` 한 줄로 정보 출력|
|다형성|배열 하나에 일반 회원과 VIP 회원을 함께 담는다|
|업캐스팅|`add(member: Member)` 에 자식 객체를 그대로 넘긴다|
|`is` 스마트 캐스트|부모 타입으로 받은 객체에서 자식만의 기능을 꺼내 쓴다|
|캡슐화|`private val members`, `var memberCnt private set`|
|`Array<Member?>` 와 null|추상 클래스라 빈 칸을 객체로 채울 수 없다 → `arrayOfNulls`|
|파일 분리|클래스마다 파일 하나 (부모·자식은 한 파일에)|

## 4. 핵심 개념

### (1) 왜 클래스로 묶는가

배열 버전에는 이런 문제가 있었습니다.

```kotlin
var totalCnt = 0     // 파일 최상위 = 자바의 static
var memberCnt = 0    // 어느 함수에서든 아무 때나 바꿀 수 있다
```

- `memberCnt = 100` 한 줄이면 프로그램이 망가지는데 **아무도 못 막습니다.**
- 회원 한 명이 `Array<String>` 3칸이라, `members[i][1]` 이 이메일이라는 걸 **외우고 있어야** 했습니다.
- 모든 함수가 `members` 배열을 매개변수로 달고 다녔습니다.

**데이터와 그 데이터를 다루는 기능이 따로 놀아서** 생긴 문제입니다. 묶으면 해결됩니다. 그게 클래스입니다.

### (2) 등급을 어떻게 나눌까 — `if` 로 나눌 것인가, 클래스로 나눌 것인가

회원에 등급이 생겼습니다. 두 가지 방법이 있습니다.

```kotlin
// 방법 1) 프로퍼티 하나로 두고 분기하기
class Member(var name: String, var grade: String) {
    fun monthlyFee(): Int {
        if (grade == "VIP") return 8000
        return 10000
    }
}
```

```kotlin
// 방법 2) 달라지는 부분만 자식이 채우기   ← 이 과제
abstract class Member(var name: String) {
    abstract fun monthlyFee(): Int
}
class NormalMember(name: String) : Member(name) {
    override fun monthlyFee() = 10000
}
class VipMember(name: String) : Member(name) {
    override fun monthlyFee() = 8000
}
```

방법 1은 등급이 늘어날 때마다 **`if` 문을 찾아다니며 고쳐야** 합니다. 그런 `if` 는 보통 한 군데가 아닙니다(요금 계산, 출력, 혜택...). 방법 2는 **클래스를 하나 더 만들면 끝**이고 기존 코드는 건드리지 않습니다.

> 💡 이것이 객체지향에서 말하는 "분기문을 다형성으로 바꾼다"는 말의 실제 모습입니다.

### (3) `abstract` — 미완성 설계도

```kotlin
abstract class Member(var name: String, var email: String, var phone: String) {
    abstract val grade: String          // 값이 없다. 자식이 반드시 채운다.
    abstract fun monthlyFee(): Int      // 본문이 없다. 자식이 반드시 채운다.

    override fun toString(): String {   // 본문이 있는 메서드도 가질 수 있다
        return "[$grade] [이름] $name, ... , [월회비] ${monthlyFee()}원"
    }
}
```

- `Member(...)` 로 **객체를 만들 수 없습니다.** "등급 없는 회원"은 세상에 없으니 맞는 제약입니다.
- 자식이 `grade` 나 `monthlyFee()` 를 구현하지 않으면 **컴파일 에러**가 납니다. 깜빡할 수가 없습니다.
- `toString()` 안에서 `monthlyFee()` 를 부르고 있지만 **부모는 그 내용을 모릅니다.** 실제로 실행되는 것은 그 객체가 어느 자식인지에 따라 정해집니다.

### (4) 다형성 — 배열 하나에 두 종류를 담는다

```kotlin
private val members = arrayOfNulls<Member>(totalCnt)   // Array<Member?>

fun add(member: Member): Boolean { ... }               // 자식 아무거나 받는다
```

`MemberManager` 에는 `NormalMember` 도 `VipMember` 도 **한 번도 등장하지 않습니다.** 그래서 등급이 10개로 늘어도 이 클래스는 그대로입니다.

```kotlin
fun totalMonthlyFee(): Int {
    var sum = 0
    for (i in 0 until memberCnt) {
        sum += members[i]!!.monthlyFee()   // if 도 when 도 없다
    }
    return sum
}
```

똑같이 `monthlyFee()` 를 부르는데 일반 회원이면 10000, VIP면 8000이 더해집니다. **어느 계산을 쓸지는 객체 자신이 압니다.**

### (5) 추상 클래스라서 치러야 하는 값 — 빈 칸을 무엇으로 채울까

배열 버전에서는 빈 칸을 `""` 로 채웠습니다. 회원이 클래스가 되면 빈 객체로 채우면 됩니다.

```kotlin
val members = Array(totalCnt) { Member("", "", "") }   // ❌ 컴파일 에러!
```

**추상 클래스는 객체를 만들 수 없으므로** 이 방법을 쓸 수 없습니다. 그래서 빈 칸을 `null` 로 둡니다.

```kotlin
private val members = arrayOfNulls<Member>(totalCnt)   // 자료형: Array<Member?>
```

대신 값을 쓸 때마다 `?.` 나 `!!` 로 null 을 처리해야 합니다.

```kotlin
if (members[i]?.email == email) { ... }     // null 이면 비교 결과가 null → 그냥 넘어간다
```

> 💡 **얻는 것이 있으면 치르는 것도 있습니다.** 추상 클래스로 안전을 얻은 대신 null 처리를 떠안았습니다. 설계에는 공짜가 없다는 것을 보여주는 좋은 예입니다.

### (6) `is` 스마트 캐스트 — 자식만의 기능 꺼내 쓰기

`sendGift()` 는 `VipMember` 에만 있으므로 `Member` 타입으로는 부를 수 없습니다.

```kotlin
val member: Member = manager.findByEmail(email) ?: return

if (member is VipMember) {
    member.sendGift()      // 이 블록 안에서는 VipMember 로 취급된다
}
```

자바처럼 `((VipMember) member).sendGift()` 로 형변환할 필요가 없습니다. `is` 로 확인하고 나면 **컴파일러가 알아서 바꿔줍니다.**

## 5. 파일 구조

배열 버전은 한 파일이었지만, 이번에는 **클래스마다 파일**로 나눕니다.

```
src/main/kotlin/member_abstract/
├── Member.kt          abstract Member + NormalMember + VipMember
├── MemberManager.kt   회원 목록과 규칙 (등급을 모른다)
├── MemberApp.kt       메뉴와 입력, 출력
└── Main.kt            조립해서 실행
```

|클래스|역할|
|---|---|
|`Member` (abstract)|회원의 공통 정보(이름·이메일·연락처)와 규약(grade, monthlyFee)|
|`NormalMember` / `VipMember`|등급별 구현|
|`MemberManager`|배열 보관 + 추가/검색/삭제 규칙. **화면 출력은 하지 않는다**|
|`MemberApp`|메뉴 출력과 입력. **데이터는 직접 만지지 않는다**|

> 💡 **코틀린은 "파일 하나에 클래스 하나"를 강제하지 않습니다.** 자바는 `public class Member` 가 반드시 `Member.java` 에 있어야 했지만, 코틀린은 한 파일에 클래스를 몇 개든 둘 수 있고 파일 이름이 달라도 됩니다.
> 그래서 **부모와 자식처럼 떼어놓고는 이해할 수 없는 클래스들은 한 파일에 묶는 것이 관례**입니다. 여기서도 `Member` 3형제는 `Member.kt` 하나에 넣습니다.
> 이름을 구분하는 단위는 파일이 아니라 **패키지**입니다. 파일 맨 위의 `package member_abstract` 가 그 역할을 합니다.

## 6. Step by Step

각 Step에 **목표 / 할 일 / 힌트 / 확인 방법**이 있습니다.

---

### Step 1. 회원 3형제 만들기 (`Member.kt`)

**목표**: 추상 클래스 `Member` 와 자식 `NormalMember`, `VipMember` 를 만든다.

**할 일**

1. `Member` 를 `abstract class` 로 선언하고, 주 생성자로 `name`, `email`, `phone` 을 받는다. (셋 다 수정 기능이 있으므로 `var`)
2. `abstract val grade: String` 과 `abstract fun monthlyFee(): Int` 를 선언한다.
3. `toString()` 을 재정의해 한 줄로 출력되게 한다.
4. `NormalMember`(10000원), `VipMember`(8000원)를 만들고, `VipMember` 에만 `sendGift()` 를 추가한다.

**힌트**

```kotlin
package member_abstract

abstract class Member(var name: String, var email: String, var phone: String) {

    abstract val grade: String              // 값 없이 선언만
    abstract fun monthlyFee(): Int          // 본문 없이 선언만

    override fun toString(): String {
        return "[$grade] [이름] $name, [이메일] $email, [연락처] $phone, [월회비] ${monthlyFee()}원"
    }
}

class NormalMember(name: String, email: String, phone: String) : Member(name, email, phone) {
    override val grade = "일반"
    override fun monthlyFee() = 10000
}

class VipMember(name: String, email: String, phone: String) : Member(name, email, phone) {
    override val grade = "VIP"
    override fun monthlyFee() = 8000

    fun sendGift() {                        // 자식만의 메서드
        println("  → $name 님께 VIP 사은품을 보냈습니다.")
    }
}
```

> 자식의 생성자 매개변수에는 `val`/`var` 을 **붙이지 않습니다.** 붙이면 부모 것과 별개인 새 프로퍼티가 생겨 버립니다. 그냥 부모에게 넘기기만 하면 됩니다.
> `abstract` 멤버는 재정의를 전제로 하므로 부모에 `open` 을 붙이지 않아도 됩니다.

**확인**: 임시로 `fun main() { println(VipMember("김VIP", "v@a.com", "010")) }` 를 실행해 한 줄이 제대로 나오면 성공. `Member("a","b","c")` 를 만들어 보고 **컴파일 에러가 나는 것도** 확인해 보세요.

### Step 2. 저장소 만들기 (`MemberManager.kt`)

**목표**: 회원 배열을 감추고, 정원과 현재 인원을 관리하는 클래스를 만든다.

**할 일**

1. `class MemberManager(planNo: Int)` — 생성자로 요금제 번호를 받는다.
2. `totalCnt` 는 `planNo * 10` 으로 정하고 `val` 로 둔다.
3. `memberCnt` 는 `var` 이되 **`private set`** 을 붙인다.
4. `members` 는 `arrayOfNulls<Member>(totalCnt)` 로 만들고 **`private`** 으로 감춘다.
5. `isFull` 을 커스텀 getter 프로퍼티로 만든다.

**힌트**

```kotlin
class MemberManager(planNo: Int) {

    val totalCnt = planNo * 10

    var memberCnt = 0
        private set                 // 밖에서는 읽기만, 바꾸는 것은 이 클래스 안에서만

    private val members = arrayOfNulls<Member>(totalCnt)    // Array<Member?>

    val isFull: Boolean
        get() = memberCnt == totalCnt
}
```

> `planNo` 앞에는 `val` 을 붙이지 않았습니다. `totalCnt` 를 계산하는 데만 쓰고 버릴 값이라 프로퍼티로 남길 필요가 없습니다.
> `private set` 이 배열 버전의 최상위 `var` 문제를 해결하는 지점입니다. 이제 밖에서 `memberCnt = 100` 을 하면 **컴파일 에러**가 납니다.

**확인**: 컴파일이 되면 성공. `MemberManager(1).memberCnt = 5` 를 써 보고 에러가 나는지 확인해 보세요.

### Step 3. 검색과 추가

**목표**: 이메일/이름으로 찾고, 회원을 추가한다.

**할 일**

1. `private fun findIndex(email: String): Int` — 이메일로 인덱스를 찾는다. 없으면 `-1`.
2. `fun findByEmail(email: String): Member?` — 없으면 `null` 을 돌려준다.
3. `fun findByName(name: String): Member?`
4. `fun add(member: Member): Boolean` — 정원 초과·중복이면 `false`.

**힌트**

```kotlin
    private fun findIndex(email: String): Int {
        for (i in 0 until memberCnt) {
            if (members[i]?.email == email) {       // Member? 이므로 . 대신 ?.
                return i
            }
        }
        return -1
    }

    fun findByEmail(email: String): Member? {
        val idx = findIndex(email)
        return if (idx == -1) null else members[idx]
    }

    fun findByName(name: String): Member? {
        for (i in 0 until memberCnt) {
            if (members[i]?.name == name) return members[i]
        }
        return null
    }

    fun add(member: Member): Boolean {
        if (isFull) return false                        // 정원 초과
        if (findIndex(member.email) != -1) return false // 이메일 중복

        members[memberCnt] = member                     // 세 칸을 채우던 것이 한 줄로
        memberCnt++
        return true
    }
```

> **`-1` 이 `null` 로 바뀌었습니다.** 배열 버전은 인덱스를 돌려줬으므로 `-1` 이 "없음"이었지만, 객체를 돌려주는 함수에서는 `null` 이 그 역할을 합니다. 받는 쪽이 **null 검사를 강제로 하게 되는 것**이 장점입니다.
> `findIndex` 는 `private` 입니다. 인덱스는 이 클래스 밖으로 나가면 안 되는 내부 사정입니다.
> 배열 버전의 `findIndex(members, col, value)` 에서 `members` 와 `col` 이 **둘 다 사라진 것**을 확인하세요. `members` 는 자기 프로퍼티라 넘길 필요가 없고, `col` 은 `.email` 이라고 쓰면 되기 때문입니다.
> `add` 는 `println` 을 하지 않습니다. **화면에 무엇을 띄울지는 `MemberApp` 이 정할 일**입니다.

**확인**: 컴파일 성공.

### Step 4. 삭제 · 전체 목록 · 매출 합계

**목표**: 삭제(+당기기)와, 화면에 넘겨줄 목록·합계를 만든다.

**할 일**

1. `fun delete(email: String): Boolean` — 찾아서 지우고 뒤를 당긴다.
2. `fun getAll(): Array<Member>` — 등록된 회원만 잘라서 돌려준다.
3. `fun totalMonthlyFee(): Int` — 월회비 합계.

**힌트**

```kotlin
    fun delete(email: String): Boolean {
        val idx = findIndex(email)
        if (idx == -1) return false

        for (i in idx until memberCnt - 1) {
            members[i] = members[i + 1]      // 세 칸을 옮기던 것이 한 줄이 되었다
        }

        memberCnt--
        members[memberCnt] = null            // 꼬리 정리도 한 줄
        return true
    }

    fun getAll(): Array<Member> {
        return Array(memberCnt) { members[it]!! }
    }

    fun totalMonthlyFee(): Int {
        var sum = 0
        for (i in 0 until memberCnt) {
            sum += members[i]!!.monthlyFee()
        }
        return sum
    }
```

> **당기기가 왜 한 줄이 되었나?** 배열 버전은 문자열 3개를 하나씩 옮겨야 했지만, 이제 옮기는 것은 **객체를 가리키는 주소 하나뿐**입니다.
> 순서는 그대로입니다: 당기기 → `memberCnt--` → 꼬리 정리.
> `getAll()` 의 `!!` 는 "여기는 null 이 아니다"라고 컴파일러에게 알려주는 표시입니다. `0 until memberCnt` 구간이 반드시 채워져 있다는 것은 **이 클래스가 보장**합니다. 그래서 돌려주는 자료형이 `Array<Member>`(물음표 없음)가 되어, 받는 쪽은 null 검사를 하지 않아도 됩니다.
> `members` 를 그대로 돌려주지 않는 이유: 밖에서 `members[0] = null` 처럼 저장소를 직접 망가뜨릴 수 있기 때문입니다.

**확인**: 컴파일 성공.

### Step 6. 회원 추가 — 등급에 따라 다른 객체 만들기

**목표**: 등급을 입력받아 `NormalMember` 나 `VipMember` 를 만들어 관리자에게 넘긴다.

**할 일**

1. `manager.isFull` 이면 안내 후 `return`.
2. 이름·이메일·연락처·등급을 입력받는다.
3. 등급에 따라 어느 클래스를 만들지 정한다.
4. `manager.add(...)` 의 결과(`Boolean`)로 메시지를 나눈다.

**힌트**

```kotlin
    private fun addMember() {
        if (manager.isFull) {
            println("회원이 꽉 찼습니다.")

        println("이름을 입력하세요.")
```

> ⭐ **이 과제에서 가장 중요한 줄입니다.** `member` 의 자료형은 무엇일까요? `Member` 입니다. `if` 의 두 갈래가 서로 다른 클래스를 돌려주지만, 둘의 **공통 부모**로 추론됩니다.
> 그리고 **어느 자식을 만들지 정하는 곳은 프로그램 전체에서 여기 한 곳뿐**입니다. 이 지점만 지나면 나머지 코드는 전부 `Member` 로만 다룹니다.
> `manager.add(member)` 에 자식 객체가 그대로 들어갑니다. 자식은 부모 자리에 들어갈 수 있기 때문입니다. (업캐스팅)

**확인**: 일반/VIP를 각각 추가하고 "일반 회원이 등록되었습니다." / "VIP 회원이 등록되었습니다."가 나오면 성공.

### Step 7. 조회 3종 — 다형성과 스마트 캐스트

**목표**: 이메일/이름/전체 조회를 만든다. VIP 조회 시 사은품 안내를 덧붙이고, 전체 조회에 매출 합계를 붙인다.

**할 일**

1. `selectByEmail()` — 찾은 뒤 출력하고, **VIP면** `sendGift()` 를 부른다.
2. `selectByName()` — 찾아서 출력.
3. `selectAll()` — 전원 출력 후 `manager.totalMonthlyFee()` 출력.

**힌트**

```kotlin
    private fun selectByEmail() {
        println("이메일을 입력하세요.")
        val email = readln()

        val member = manager.findByEmail(email)
        if (member == null) {
            println("찾으시는 정보가 없습니다.")
            return
        }

        println(member)                 // 등급에 맞는 toString() 이 자동으로 골라진다

        if (member is VipMember) {      // is 로 확인하면 그 안에서는 VipMember 다
            member.sendGift()
        }
    }

    private fun selectAll() {
        val all = manager.getAll()
        if (all.isEmpty()) {
            println("등록된 회원이 없습니다.")
            return
        }

        for (i in all.indices) {
            println("${i + 1}. ${all[i]}")
        }

        println("월 예상 매출 : ${manager.totalMonthlyFee()}원")
    }
```

> `println(member)` 한 줄이면 됩니다. 배열 버전의 `printMember(members[idx])` 가 사라진 이유는, **출력 방법은 회원 자신이 제일 잘 아는 정보**라 회원 클래스가 가져갔기 때문입니다.
> 배열 하나에 일반 회원과 VIP 회원이 섞여 있는데도 **구분해서 꺼낼 필요가 없습니다.** 각 객체가 자기 `toString()` 을 알고 있습니다.
> `null` 검사를 빼먹으면 **컴파일이 되지 않습니다.** 배열 버전에서 `idx == -1` 검사를 깜빡해도 컴파일이 됐던 것과 비교해 보세요.

**확인**: VIP를 조회하면 사은품 줄이 나오고, 일반 회원을 조회하면 안 나오면 성공. 전체 조회의 매출 합계가 등급별로 다르게 더해지는지 확인하세요.

**목표**: 남은 두 기능을 완성한다.

## 7. 배열 버전과 달라진 점 정리

|배열 버전|추상 클래스 버전|
|---|---|
|`var totalCnt` / `var memberCnt` (파일 최상위 = static)|`MemberManager` 의 프로퍼티 (객체마다 따로)|
|누구나 `memberCnt` 를 바꿀 수 있다|`private set` — 밖에서는 읽기만|
|`Array(3) { "" }` 한 행이 회원 한 명|`Member` 객체 하나|
|`members[i][1]`|`members[i].email`|
|`fun addMember(members, ...)` — 배열을 계속 넘김|`manager.add(member)`|
|`findIndex(members, col, value)` — 열 번호로 구분|`findByEmail` / `findByName` — 이름으로 구분|
|못 찾으면 `-1`|못 찾으면 `null` (검사를 강제한다)|
|`printMember(member)` 함수|`toString()` 재정의 → `println(member)`|
|등급을 넣으려면 `if (grade == "VIP")` 를 여기저기|자식 클래스가 알아서 (분기문 없음)|
|삭제 시 세 칸을 하나씩 복사|`members[i] = members[i + 1]` 한 줄|
|빈 칸을 `""` 로 채움|추상 클래스라 못 채움 → `null` + `?.` / `!!`|
|파일 하나|클래스별 파일 4개|

**먼저 다듬으면 좋은 점**

1. **수정 기능의 구멍 막기** — `updateMember` 는 객체를 직접 고치기 때문에 **남의 이메일로 바꿔도 막지 못합니다.**
   `MemberManager` 에 `update(email, newName, newEmail, newPhone): Boolean` 을 만들어 중복 검사를 통과한 값만 반영하도록 옮겨 보세요. **규칙은 규칙을 아는 클래스가 가져야 합니다.**

2. **빈 입력 막기** — `Member` 의 `init` 블록에서 검사하거나 `MemberApp` 에서 `isBlank()` 로 걸러 보세요.

3. **실패 이유 구분하기** — `add` 가 `false` 를 돌려줄 때 '정원 초과'인지 '중복'인지 알 수 없습니다. 지금은 `MemberApp` 이 `isFull` 을 미리 물어봐서 피하고 있습니다. `enum class` 를 배우면 세 가지 결과를 그대로 돌려줄 수 있습니다.

**확장 도전 과제**

1. **등급 추가하기** ⭐ — 학생 회원(5000원)을 추가해 보세요. `StudentMember` 클래스 하나 + `MemberApp` 의 등급 선택지 한 줄이면 끝입니다.
   **`MemberManager` 를 한 글자도 안 고쳐도 되는지 직접 확인하세요.** 만약 `if (grade == "VIP")` 방식이었다면 몇 군데를 고쳐야 했을까요? 이 비교가 이 과제의 핵심입니다.
2. **등급 승급** — 일반 회원을 VIP로 올리려면? 객체의 클래스는 바뀌지 않으므로, 같은 정보로 `VipMember` 를 새로 만들어 기존 회원을 지우고 넣어야 합니다. `MemberManager.upgrade(email)` 을 만들어 보세요.
3. **요금 구조 바꾸기** — 지금은 등급마다 요금이 고정값입니다. 부모에 기본 요금 10000을 두고 자식은 **할인율만** 정하게 바꿔 보세요.
   ```kotlin
   abstract val discountRate: Int
   fun monthlyFee() = 10000 * (100 - discountRate) / 100
   ```
   이러면 요금 인상 때 부모 한 곳만 고치면 됩니다.
4. **VIP만 조회** — 전체 조회에서 `is VipMember` 로 걸러 VIP만 출력하는 메뉴를 추가해 보세요.
5. **정렬** — 월회비가 높은 순으로 전체 조회를 출력해 보세요.
6. **인터페이스와 비교** — `abstract class` 대신 `interface` 로 만들면 어떻게 될까요? 인터페이스는 **생성자가 없어서** `name`/`email`/`phone` 을 물려줄 수 없습니다. 각 자식이 세 프로퍼티를 직접 선언해야 합니다.
   👉 그래서 **공통 상태가 있는 이번 경우는 추상 클래스가 맞습니다.** 인터페이스가 어울리는 경우는 다음 과제(`회원관리만들기(인터페이스)`)에서 다룹니다.

### 한 줄 정리

> 이 과제는 **`if` 로 나누던 것을 클래스로 나누는** 연습입니다.
> 등급이 하나 늘어날 때 `if` 방식은 프로그램 전체를 뒤져야 하지만, 다형성 방식은 클래스 하나를 추가하고 끝냅니다.
> 그리고 그 대가로 `Array<Member?>` 의 null 처리를 떠안았습니다. **설계에는 공짜가 없다**는 것까지 함께 확인해 보세요.
